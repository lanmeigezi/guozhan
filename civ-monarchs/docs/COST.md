# AI 调用成本控制指南

## 1. 默认零成本

- `config/monarchs.json` 里 12 个席位默认 `adapter: "deterministic"`：离线确定性君主，不产生任何 API 调用。
- `config/seats.json` 默认 `defaultControl: "ai"` + `autoFill: true`：缺人时由人机补位，不调用外部模型、不产生费用，也保证十二国行为一致（席位盲化的行为层保障）。
- DM 模型默认关闭（未设 `CIV_DM_KEY` / `CIV_DM_MODEL`），由 Harness / 人工提交修正。
- 也就是说：**不配 Key，整局推演完全离线、可复现、零费用**。这是验收与演示的推荐状态。

## 2. 成本公式

```
单局成本 ≈ 回合数 × 已启用席位数 × (输入 token + 输出 token) × 模型单价
```

本包的固定上限（`config/rules.json` 的 `rules.ai`）：

| 项 | 默认 | 作用 |
|---|---|---|
| `concurrency` | 3 | 12 席分 4 批并发，避免瞬时打满限流 |
| `timeoutMs` | 15000 | 单席超时即降级离线君主 |
| `maxTokensPerDecision` | 320 | 单席单次输出上限 |

输入侧：每席 prompt 约 250–450 token（本国快照 + 列强摘要 + 合法动作样例 + 系统契约）。
输出侧：一个意图 JSON，实测 40–120 token，上限 320。

**量级估算（以 60 回合、12 席全开为例）**：`60 × 12 × (约 400 输入 + 约 100 输出) ≈ 36 万 token`。按各家模型实际单价换算即可；国产 OpenAI 兼容端点通常远低于海外旗舰模型。DM 模型若每回合都开，再乘约 1/12 的增量。

## 3. 降本手段（按优先级）

1. **不必 12 席全开**：只给想对比的 3–4 个席位配 Key，其余保持离线 —— 这正是「12 个模型」实验里最省钱的对照组做法。
2. **低频触发**：不要每回合都点「12 模型自动推演」。关键节点（时代跃迁、战争、临近胜利）才 `POST /auto`；中间回合用离线或人工下令。
3. **缩短 prompt**：`src/ai/prompts.js` 里 `monarchUser` 的合法动作样例目前取前 18 条，可再调小；`rivals` 取前 6 国。
4. **降级纪律**：超时、缺 Key、输出不合法 JSON 一律降级，不重试、不加倍调用；`requestId` 幂等键也防止重复扣费。
5. **便宜模型**：君主层只需要输出一个结构化意图，用轻量/快速档即可；把强模型留给 DM 叙事或关键回合。
6. **DM 只在需要时开**：`POST /auto` 不带 `includeDm`；或让 Harness（酒馆里的你）手工提交 1–2 条修正，比模型自动出更省。

## 4. 延迟控制

- 模型调用在 `src/ai/director.js` 里异步并发，**不进入确定性主循环**；`advanceTurn` 是纯同步计算，几毫秒完成。
- 超时 15s 是硬上限；12 席并发 3 的最坏情况约 4 批 × 15s = 60s。可将 `timeoutMs` 调低到 6000 以适配演示。
- 酒馆扩展与网页客户端在 `/auto` 期间不阻塞界面（fetch 异步），SSE 仍可推送其他事件。

## 5. 风险与限制

- 本包不记录、不回显任何 API Key；`GET /models` 只返回席位模式与模型 ID。
- 模型输出结构不合法时会被 `validateDecisions` 拒绝并降级，不会污染状态。
- 编年史/台词里可能有人写「忽略之前指令」，已由系统提示词 + 注入包裹双重防御；但它仍会占输入 token，必要时可在 `wrapAsGameData` 前截断长度。
