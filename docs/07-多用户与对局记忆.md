# 多用户管理与对局记忆接入（2026-11-01）

本文说明国战服务端的账号 / 房间大厅 / 房主管理，以及给酒馆/外部压缩器使用的完整对局记忆接口。

## 1. 账号系统

账号库是 `data/users.db`（独立于每房间游戏库），首次启动自动建表：

- `users`：用户名（规范化小写）、昵称、scrypt 密码哈希（16 KB salt + 64-byte key）、角色、时间戳；
- `sessions`：会话令牌只存 SHA-256 哈希，默认 7 天过期；
- `room_hosts` / `room_members` / `room_bans`：房主、成员席位、房间封禁关系。

密码用 `node:crypto.scryptSync`，登录验证用 `timingSafeEqual`；明文密码和原始会话令牌都不落库。

### HTTP 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | `{username,password,displayName?}` → `{user,token}`；用户名唯一（大小写不敏感） |
| POST | `/api/auth/login` | `{username,password}` → `{user,token}`；错误一律 `INVALID_CREDENTIALS`，不枚举用户名 |
| POST | `/api/auth/logout` | Bearer 账号令牌 → 使会话失效 |
| GET | `/api/me` | 当前账号、加入的房间、房主房间 id |
| GET | `/api/admin/users` | 管理令牌查看账号列表（不含密码/会话） |

账号令牌形如 `usr_...`；席位令牌仍是 `gz_...`。**两者不能混用**：账号令牌只用于大厅/房间管理，进入对局后仍使用加入房间时签发的席位令牌（角色、迷雾、CAS 仍按席位）。

网页首屏是**桌游大厅**（`#hall`）：顶部先登录（用户名/密码/昵称，或已登录时退出），再选桌游。未登录时其余 6 款卡片标「先登录」并被拦截（建房/刷新大厅/打开桌游服务按钮一并禁用）；选「国战 · 六角棋」后才展开房间大厅 / 剧本选择 / 新建房间，建房或加入成功后大厅收起、进入沙盘，顶栏「大厅」可随时回来，沙盘连接还在时大厅右上角给出「回到沙盘」。其余 6 款（UNO / 斗地主 / 炸弹猫 / 骗子酒馆 / 大富翁 / 狼人杀）跑在独立的桌游服务里（默认 `http://<主机>:8766/`，`npm run start:board`），大厅只提供地址入口并把地址记在 `localStorage`（`guozhan_board_service_url`）。

> 这道闸门只是网页层的门禁：桌游服务是独立进程、不带账号体系，直接访问 8766 仍然能进。要硬拦必须在桌游服务里校验国战令牌（共享密钥或回调 `/api/me`）。


账号会话保存在本机 `localStorage`（`guozhan_account_token`）；席位令牌仍只驻留页面内存。服务器地址记在 `guozhan_server_url`，刷新后自动恢复——恢复会话只在 401 时清令牌，网络不通时保留令牌并提示，改好地址即可自动重试。

## 1.1 断线回来（继续对局）

没打完的对局不会因为关页面而丢：房间与成员关系都在服务端 SQLite 里，账号重新登录（或刷新页面自动恢复会话）后，`/api/me` 会把仍在进行（`phase !== 'ended'`）的房间带回来，大厅顶部出现「继续对局」卡片（房间名、剧本、T 回合、席位），点一下即回到原席位。`localStorage` 里的 `guozhan_last_room` 只用来给上次那局加「上次在对局中」标签，不参与鉴权。

回来的实现是 `POST /api/rooms/{id}/join`：账号已是成员 → `reclaimSeat` 旋转该席位的令牌并返回新令牌（旧令牌**立刻 401**，另一台设备上的旧标签页会被踢下线）；席位已不存在则按普通加入处理。已结束（`phase === 'ended'`）的房间不会出现在「继续对局」里，仍在「我的房间」列表可查。

酒馆侧同样走这条路：扩展设置里填账号 + 密码 + 房间 ID，点「登录并领席位」→ `usr_` 登录 → 领取/找回席位 → 用 `gz_` 连接；密码用完即清，账号令牌只存内存。

## 2. 房间大厅与房主管理

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/rooms` | 账号/管理令牌 | 房间列表（带房主、成员） |
| POST | `/api/rooms` | 账号/管理令牌 | 建房；账号建房自动成为房主 |
| GET | `/api/rooms/:id` | 账号/成员/管理 | 房间详情 + 房主/成员 |
| POST | `/api/rooms/:id/join` | 账号/管理 | 加入一个可认领席位或观战；同一账号只占一个席位，重复加入会重签席位令牌 |
| POST | `/api/rooms/:id/kick` | 房主/管理 | `{userId, ban?, reason?}`；踢出后该席位立即失效，可同时封禁 |
| POST | `/api/rooms/:id/unban` | 房主/管理 | `{userId}` 解除房间封禁 |
| POST | `/api/rooms/:id/leave` | 账号成员 | 离开；房主必须删除房间或转移房主（本轮未做转移） |
| DELETE | `/api/rooms/:id` | 房主/管理 | 删除房间及成员/封禁关系 |

- 踢人时该人类席位会切回 `ai`，避免对局卡在一个空的人类席位上；被踢账号的旧席位令牌立刻被撤销。
- 房间封禁只影响该房间，不封账号登录；`/api/me` 与大厅仍可访问。
- 一个进程内同一房间的账号只能有一个席位；观战席位也占成员关系。
- 账号会话与席位令牌是不同层次：会话过期/服务重启后，席位关系还在，但需要重新加入/认领（房主可重新签发）。

### 安全边界

- 管理令牌（`GUOZHAN_TOKEN`）仍是最高权限；账号系统不替代它。
- 建房/踢人/删除没有额外 CSRF token，依赖 Bearer + Origin 白名单；公网部署请放在 HTTPS 反代后，并加登录限速/审计。
- 本轮未做：邮箱验证、找回密码、账号注销、好友/黑名单、跨房间全局封禁、房主转移。这些是下一层用户中心能力。
- 桌游合集（board-games）目前仍是“房主 + 席位 + AI/LLM 座位”的房间模型，尚未接入这套账号库；账号系统先落地在国战服务端。

## 3. 完整对局记忆

`GET /api/rooms/:id/memory` 返回 `memory.format = "guozhan-match-memory"`：

- `room`：房间、剧本、种子、当前回合、阶段、胜者/终局原因、创建/更新时间；
- `seats`：席位、势力、类型、连接状态（不含令牌）；
- `turns[]`：逐回合 `stateDigest`、**已按受众裁剪的事件**、本席位命令（观战为全部）、基线/钳制/拒绝、叙事；
- `events[]`：与 `turns[].events` 同源的原始事件流（offset/turn/type/payload），方便外部压缩器自行重建；
- `messages[]`：外交文书；玩家只拿公开或与自己席位相关的文书；
- `viewer`：`{recipient, seatId, factionId, full}`。

权限：

- 玩家席位：只拿该席位的命令、叙事、拒绝、势力基线，以及 `audienceIncludes` 允许的事件；**不能通过记忆接口绕过战争迷雾**。
- 观战席位 / 管理令牌：`full=true`，拿全知历史。

酒馆扩展新增「同步完整对局记忆」按钮，走 `client.memory()` 拉取原始 JSON，用 `wrapAsGameData` 包裹后交给 `extension_prompt`（或降级写 `extensionPrompts` / `localStorage`），**不在扩展侧截断或压缩**；压缩由酒馆角色卡/工具完成。

### 示例

```bash
curl -H "Authorization: Bearer $SEAT_TOKEN" \
  "http://127.0.0.1:8788/api/rooms/$ROOM_ID/memory"
```

返回结构可直接落到外部记忆库，再按 `turns[].turn` 或 `events[].offset` 做增量压缩；`generatedAt` 是本次拉取时间，不代表状态版本。

## 4. 存储与验证

- 账号库：`data/users.db`（WAL）；房间游戏库仍是 `data/rooms/<roomId>.db`。
- 测试：`tests/deterministic/memory.test.ts`（观战全知 vs 玩家裁剪）、`tests/deterministic/adapters.test.ts` A5/A6/C9（注册/登录/大厅/踢人封禁/记忆路由）。
- 备份：随 `data/` 一起备份；`users.db` 不包含游戏状态，删库只影响账号/房间成员关系，不影响已导出的 `rooms` 存档。
