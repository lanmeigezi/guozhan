# 回合复盘、开荒模式与自定义地图（2026-10-30）

本文记录本轮新增的三块内容：

1. **回合复盘**：每个结算回合生成 `turn_recap` 事件，列出所有势力的领地/金/粮/民心/兵力变化；
2. **开荒模式 `frontier`**：开局每方 1 格，空白地有原住民与少量资金，必须派兵进入并完成基建 Lv1 才能占领；
3. **自定义地图/地名/国名**：`frontier` 是一个可直接编辑的静态自定义地图示例，地图、地名、国家名和颜色都在该剧本目录内。

> 兼容边界：新剧本 `frontier` 独立目录、独立 contentHash；旧剧本（aria / warring-states / iron-front / random-front / random-front-v2 / grand-front）的内容哈希与行为不变。
> `turn_recap` 是新增事件，旧房间读旧战报不受影响；新结算回合会带该事件。

---

## 1. 回合复盘

### 1.1 数据来源

`src/core/apply.ts` 在每回合末尾、`turn_resolved` 之前生成：

```json
{
  "type": "turn_recap",
  "turn": 12,
  "factions": [
    {
      "id": "red",
      "name": "赤原裔",
      "regionsBefore": 3,
      "regionsAfter": 4,
      "regionsDelta": 1,
      "goldDelta": 420,
      "foodDelta": -180,
      "moraleDelta": 2,
      "troopsBefore": 24000,
      "troopsAfter": 31000,
      "eliminated": false
    }
  ]
}
```

- **所有势力**都会出现，包括本回合灭亡的势力（`eliminated=true`）；
- 数值来自回合前状态与裁决后状态的真实差值，不是 LLM 叙述；
- `turn_recap` 是公开事件（`EVENT_VISIBILITY: all`），观战端也可见；
- 旧的 `turn_resolved`（逐字段 delta）与 `TurnReport.baseline` 保留，复盘是它们的“按势力聚合视图”。

### 1.2 UI

- **网页**：左侧新增「回合复盘」面板，显示每个势力的领地 `before→after`、金/粮/民心/兵力变化；数据从 `TurnReport.events` 里的 `turn_recap` 读取。
- **酒馆扩展**：事件日志输出一行 `📊 Tn 复盘：…`。
- **桌游合集**：结算报告的 `turn_recap` 事件被转成一行摘要（最多 6 个势力）。
- 复盘不会改变任何状态；它只是同一份确定性结果的压缩展示。

### 1.3 闸门

`tests/deterministic/frontier.test.ts` 里的「turn_recap 覆盖全部势力」断言：事件包含所有势力的 `regionsBefore/After`、`goldDelta` 等字段。

## 2. 开荒模式（`frontier`）

### 2.1 开局

`config/scenarios/frontier/` 是独立静态剧本：

- 地图 19 格，4 个自定义国家，各只占 1 格（首都）；
- 地图为 **半径 2 的正六边形蜜格**（19 格，无空洞；`hexSize=60`，画布 536×496），不再复用战国剧本的 1200×820 稀疏坐标；
- 4 个首都固定在正六边形的四个对称角：左上 `風息原`（红）、右上 `鳴泉谷`（蓝）、左下 `鹽鹼灘`（青）、右下 `孤城`（金）；四个角格在棋盘上的相邻格数相同（各 3），不再出现某个出生点天然多一格接壤。这一步只改布局，规则邻接仍按 `regions.json`，不额外改玩法；
- 其余 15 格是 **荒地**：`owner=null`，由 `factions.json.neutralTerritories` 放置原住民守军（`militia`，350–700 人），并在区域资源中带少量金；
- 每个国家开局有 1 支陆军（约 1.2–1.5 万）和 1 支民兵；
- 4 国只有 1 场初始战争（红/蓝），其余中立；所有国家都能向荒地扩张。

### 2.2 占领流程

1. **派兵进入荒地**：`move_units` 目标为无主地块；shared movement 允许穿越中立地，因此可直接进入。
   - 荒地有原住民守军；普通 `attack` 可以驱散/杀伤原住民，但 **不能占领**（见 2.3）。
2. **开荒（`settle_region`）**：部队已在该地块后，合法动作列表出现「开荒 X（基建 Lv1）」。
   - **派兵与开荒必须分两回合**：执行开荒的部队本回合不能刚移动过，否则拒绝 `FRONTIER_NEEDS_NEXT_TURN`；这条同时约束 UI 与 HTTP，避免前端看起来不能做、API 却能绕过的双标；
   - 要求本区本方兵力 ≥ 原住民 × `nativeTroopRatio`（默认 1）；快照里的 `requiredTroops` 就是该阈值；
   - 要求没有其他势力的部队在该区；
   - 支付 `settleGoldCost` 金 + `settleFoodCost` 粮；
   - 原住民守军被吸收：按 `nativeManpowerRatio` 转化为兵源；
   - 获得地块的少量资金：`round(baseGold × lootGoldRatio)`；
   - 区域 `owner=fid`，基建直接设为 `settledInfrastructure`（默认 Lv1）；
   - 发 `frontier_settled` 事件。
3. 开荒完成后该区成为普通领地，可继续按 governance 规则升级基建 Lv2+、征兵、驻军、被进攻。

### 2.3 普通进攻为什么不能直接抢荒地

`combat.ts` 对 `owner=null && world.frontier` 的地块强制 `captured=false`：攻击只结算原住民伤亡，不改变归属。
因此“占空地”必须走开荒流程；这条规则防止玩家绕开基建成本直接吞地。

### 2.4 参数

`config/scenarios/frontier/frontier.json`：

| 键 | 当前值 | 作用 |
|---|---:|---|
| `settleGoldCost` | 100 | 开荒金成本 |
| `settleFoodCost` | 80 | 开荒粮成本 |
| `lootGoldRatio` | 0.18 | 开荒获得 `baseGold × 0.18` 的少量资金 |
| `nativeTroopRatio` | 1 | 需要 ≥ 原住民数量的本方部队 |
| `nativeManpowerRatio` | 0.5 | 原住民按 50% 转化为兵源 |
| `settledInfrastructure` | 1 | 开荒即完成的基建等级 |

### 2.5 快照/UI

`ProjectedRegion.frontier` 在无主荒地上下发：

```ts
frontier?: {
  natives: number;
  requiredTroops: number; // ceil(natives × nativeTroopRatio)
  lootGold: number;
  goldCost: number;
  foodCost: number;
  infrastructure: number;
};
```

网页/酒馆/桌游区域详情显示“未开垦荒地：原住民 X（需本区兵力 ≥ Y）；派兵进入后开荒…；派兵与开荒分两回合；普通进攻不能占领”，动作列表显示「开荒」分组。网页与桌游结算战报会列出本席位被拒的军令（`rejected`），不再只弹一次提交提示。

### 2.6 子代理实际试玩（2026-10-31）

让一个独立子代理以红方席位通过 HTTP 实际打了 9 回合，暴露并修复了以下问题：

1. **结算时才拒、战报里看不到**：提交返回 `completed` 只代表入队，资源不足/条件不满足要到结算才拒。现在网页与桌游战报显示 `rejected`，并带拒绝码与原因。
2. **荒地详情没写兵力门槛**：区域详情只写原住民数量，玩家不知道要带多少兵。快照新增 `requiredTroops`，三端都显示“需本区兵力 ≥ Y”。
3. **UI 不能同回合移动+开荒，HTTP 却能**：这是前后端双标，比“UI 少个按钮”严重。核心已强制“派兵与开荒分两回合”（`FRONTIER_NEEDS_NEXT_TURN`），合法动作空间也不再给刚移动部队生成开荒动作，UI 文案同步说明。
4. **招兵卡“征 18000”却写“本区上限 1800”**：1800 是兵源（manpower），18000 是折算后的士兵数。动作说明改为“本区兵源上限 X（每 1000 兵耗 Y 兵源），本次可征 Z 兵”。
5. **都城已失守仍显示“都城 风息原”**：网页与酒馆侧栏现在检测首都当前归属，失守时标注“已失守/失守”；桌游地图的首都标记本来就按归属绘制，会自然消失。

试玩结果：红方 9 回合占领 3 块荒地、攻下 2 座城，但首都風息原被金丘裔夺走，最终 3 区、未分胜负。说明开荒路径可玩，但首都防守仍是人类玩家需要认真处理的风险点。

## 2.7 地图几何与出生点（2026-10-31）

初版 `layout.json` 直接复用了战国剧本的 1200×820 稀疏坐标，19 格在画布上拉得很开；中间版本又用了 135px 等距方阵，六角格之间留下明显缝隙。现改为**正六边形蜜格**：

- 半径 2 的六边形棋盘：顶/底行各 3 格、中间依次 4/5/4/3，共 19 格，无空洞；
- 画布 536×496，`hexSize=60`，格与格边贴边；
- 四个首都固定在四个对称角格（左上、右上、左下、右下），四角格在棋盘上的相邻格数相同（各 3），出生点视觉与地格邻接对称；规则邻接图未改，避免打乱已有 AI 平衡；
- 布局重新做过图匹配：30 条规则邻接里 23 条落在蜜格相邻边上；原邻接图本身非平面，剩余 7 条仍是规则道路；
- 规则邻接仍以 `regions.json` 为准，`layout.json` 只决定画在哪；改坐标不会改变合法性。

## 2.8 AI 自对弈调参（2026-10-30）

初版 frontier 的 AI 实测有两个明显问题，已修：

1. **AI 把命令浪费在“攻击荒地”**：荒地普通攻击不能占领，AI 在 60 回合仍只有 1–4 块地。
   - 修复：`legal.ts` 不再为无主荒地生成普通进攻动作；`heuristic.ts` 也过滤这类攻击。
   - 开荒模式增加扩张优先：有可开荒地块时最多同时开 2 块；没有时最多派 2 支部队进入相邻荒地；开局前 3 块地阶段跳过基建/法令/谍报/筑垒等内政命令。
2. **两家出生首都相邻 + AI 不占荒地**：疾攻可以开局直接打守成/无常，导致原型失衡。
   - 四个首都改为互不相邻（红=風息原、蓝=晉陽、青=新鄭、金=孤城），所有首都 3–4 个邻格。
   - 无常型在 frontier 先按均衡方略生成计划，再确定性随机丢掉最多 1 条命令，既有随机性也会开荒。
   - 疾攻型在 frontier 多 1 条命令（最多 6 条），弥补开荒期兵力分散。

**80 局纯 AI 基准（60 回合上限，2026-10-30）**：

- 按原型胜场：疾攻 **13**、守成 **23**、无常 **18**；
- 按国家：金丘 **24**、蒼河 **15**、青林 **8**、赤原 **7**；
- 平均 **46 回合**；80 局中 54 局在 60 回合内产生胜者，26 局仍为平局（网页默认不限回合，实际会继续打）。

这不是“三原型完全等胜率”，但三种原型都能赢、都能扩张；金丘/蒼河的出生位置仍略占优。后续若要进一步拉平，优先调 `frontier` 的首都位置与初始兵种，而不是再提高税额/动乱。

## 2.9 回合上限与河流地块（2026-10-31）

- **回合上限**：网页快速开局与桌游开局默认 `unlimitedTurns=true`，服务端把 `world.maxTurns` 覆写为 `0`，即真正不限回合；`scenario.json.meta.maxTurns=60` 只是未勾选“不限回合”或直接调 API 时的兜底，AI 自对弈基准另行显式传 60 回合上限以便比较。
- **河流地块**：`frontier` 的 `jiangdong`（霧隱澤，`terrain=river`）是唯一水乡地块；网页与桌游现在给它叠加明显水色，酒馆端本来就按地形填色。`frontier` 没有 `waterRoutes` / `ports`，所以没有水师航线；跨水航线只存在于 `iron-front` / 超大陆等带水路的地图。

## 2.10 地块平民与地方产出（2026-10-31）

以前“非军队人口”只在势力级存在（全国总人口 − 全国兵力），地块详情看不到，也不影响田赋/矿税。现在补成可解释的一层：

- **地块人口**：`baseManpower × (1 + 0.25 × (基建等级 − 1))`，即这块地的人口潜力。
- **地块平民**：`max(0, 地块人口 − 本区全部驻军)`。它只看本区，和势力级“全国平民”是两个口径：前者用于地方产出与地块详情，后者继续用于全国税收和兵源增长。
- **地方产出**：`frontier.json.civilianLaborPenalty` 控制平民对本地粮/金产出的影响，默认 `0.35`：
  `劳动系数 = 1 − 0.35 × (1 − 本区平民 / 本区人口)`
  本区粮产/金产 = 原有地形、基建、法令、动乱乘数 × 劳动系数。满驻军时最多降 35%，空驻军时不受影响；旧剧本没有该字段（按 0 处理），行为不变。
- **示例**：首都人口 13.5 万、驻军 2.3 万 ⇒ 平民 11.2 万（83%），劳动系数 `1 − 0.35 × 17% ≈ 0.94`，本区粮/金产出约 ×0.94；把驻军调走后平民占比上升，产出恢复。
- **UI/说明**：网页、酒馆、桌游的地块详情都显示“人口 / 平民（占比）”，frontier 还会显示“本区粮/金产出 ×N”；征兵动作说明会提示“征兵会减少本区平民，从而降低本区粮/金产出”；桌游规则摘要也写明这条。
- **边界**：这次只改了 frontier 的地方产出；全国税收仍按“全国平民”计算，兵源增长仍按“全国平民占比”计算，避免一次性改动旧剧本的全局平衡。若要推广到所有模式，建议后续把 `civilianLaborPenalty` 抽成通用 economy 参数，而不是复制 frontier 配置。

## 3. 自定义地图 / 国家地名

`frontier` 既是开荒剧本，也是**自定义模式模板**。所有地图与命名数据都在 `config/scenarios/frontier/`：

| 文件 | 可改什么 |
|---|---|
| `regions.json` | 区域 id、地名 `name`、地形、邻接、基础粮/金/兵源、是否港口 |
| `layout.json` | 六角格像素坐标、画布、国家颜色、首都映射 |
| `factions.json` | 国家 id、国家名、君主名、颜色、首都、初始领地、初始金粮民心、法令、部队 |
| `frontier.json` | 开荒成本、原住民转化、开垦基建等级 |
| `scenario.json` | 剧本名/描述/回合上限/模块表/席位/知识文件路径 |

### 3.1 改地名/国名

- 改 `regions.json[].name` → 地图、区域详情、战报、LLM 地图文本一起变；
- 改 `factions.json[].name` / `ruler` / `color` → 列国面板、地图颜色与战报一起变；
- 不需要改代码。

### 3.2 改地图拓扑

- 编辑 `regions.json` 的 `adjacency`：必须**双向对称**、目标 id 必须存在；
- 编辑 `layout.json` 的 `regions[].x/y`：只影响视觉，不影响规则邻接；
- 如果新增/删除区域，同时改 `factions.json.territories` 与 `neutralTerritories`：每个区域必须属于一个国家、或列入中立/荒地，不能两者都占；
- 改完跑：
  ```bash
  npm run validate-config
  node --experimental-strip-types --test tests/deterministic/config.test.ts
  node --experimental-strip-types --test tests/deterministic/map-layout.test.ts
  ```

### 3.3 新增一个自定义剧本

1. 复制 `config/scenarios/frontier/` 到 `config/scenarios/my-map/`；
2. 改 `scenario.json.meta.id` 为目录名，改名称/描述/回合上限；
3. 按 3.1/3.2 改地图和势力；
4. 服务端目录扫描会自动发现新剧本（`/api/scenarios`）；
5. 若要在**网页快速开局**下拉里出现，还要把该剧本加入 `web/app.js` 的 `QUICKSTART_SCENARIOS`；
6. 若要进**桌游合集内置 bundle**，还要把 id 加入 `scripts/build-uno-engine.ts` 的固定剧本列表与 `src/integration/uno-session.ts` 的 `SCENARIO_ORDER`，再跑 `npm run build:uno` 与 `npm run build`；
7. 重跑 `npm run verify`。

> 当前没有运行时“地图编辑器”HTTP 接口；自定义方式是编辑 `config/scenarios/<id>/` 的静态 JSON，再由服务端装载。这样地图/名字仍走同一份 contentHash 与 fail-closed 校验，不会出现“网页改了但服务端不认”的第二份真相。

### 3.4 兼容

- `frontier` 是独立 contentHash；旧剧本哈希不变；
- 旧房间的 `turn_recap` 不存在时 UI 显示占位，不影响读取；
- 新事件/新命令全部是追加，旧客户端遇到未知事件应忽略（协议约定）。
