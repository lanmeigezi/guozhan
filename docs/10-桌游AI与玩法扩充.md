# 桌游 AI 与玩法扩充（2026-11-19）

范围：`board-games/core/src/{doudizhu,exploding,monopoly}.js`。全部为规则层改动，Host / 传输 / WebView 资源零改动；新增动作均走 Host 原有白名单校验，LLM 只做决策建议。

## 0. 调研结论（GitHub 现成方案）

| 需求 | 现成候选 | 结论 |
|---|---|---|
| 斗地主 AI | 快手 `DouZero`（ICML 2021，有预训练权重）、`RLCard`、`godmoves/dou-ai` | **不能直接搬**：全部 Python/PyTorch，无官方 JS/ONNX 推理；本仓库是零依赖 JS core（含 WebView / 蓝牙离线场景）。 |
| 大富翁规则引擎 | `HumanSean/javascript-monopoly` 等 | **不能搬**：都是 UI 复刻，不是可移植规则引擎。缺的是交易/拍卖等互动规则，自行实现。 |
| 炸弹猫休想卡 | 桌游原版规则（Nope card） | **不需要外部技术**：引擎已有 `pendingDefuse` / `pendingFavor` 反应窗口模型，照此扩展。 |

仓库里本来就有的现成机制：LLM 席位（`agent.js` + `llm-local.js` + `Host._driveLlm` / `_llmFallback`）对全部游戏通用，斗地主无需重接，只需补测试固定行为。

## 1. 斗地主 AI：本地强化 + LLM 可选升级

### 1.1 本地启发式（`aiDoudizhu`）

旧版 `aiDoudizhuLegacy` 保留为 A/B 基线与兜底。新版：

1. **手牌分解搜索**：`shapesOf()` 枚举单/对/三/三带/顺子/连对/飞机（含翅膀）/炸弹/王炸/四带二；`minTurns()` 递归求最少手数，带记忆化 + 节点预算（20000），预算耗尽回落到「一张一张出」的确定上界。估值整数、无随机、无时间依赖。
2. **记牌**：`DoudizhuGame.played` 记录所有公开出牌（斗地主出牌本就公开）；`higherOutside()` 计算外面还剩几张比我大的牌，用于首出单张与残局判断。
3. **残局优先**：能一手走完必出；对手 ≤2 张时压制优先；炸弹/王炸在对手牌多时留作后手。
4. **农民配合**：队友压住地主时不抢（除非自己能一手走完）。
5. **绝不发非法牌**：所有候选仍统一过 `legalCardIds()`；tie-break 用 cardIds 字典序，保证确定性。

叫分也改为 `bidPower()`：大牌 + 炸弹 + 手数估值，替换原来的「A 以上张数」粗判。

### 1.2 实测 A/B

跑法（可复跑，数字来自本轮实跑）：

```bash
node board-games/scripts/doudizhu-ai-bench.mjs 60
```

60 局、席位轮换、同一批种子分别让新 AI 与旧 AI 坐同一席位，对手固定旧 AI：

```json
{ "games": 60, "newWins": 29, "oldWins": 23,
  "newWinRate": 0.4833, "oldWinRate": 0.3833, "illegalActions": 0 }
```

即新 AI 胜率 **48.3%** vs 旧 **38.3%**，零非法动作。样本仅 60 局，用于证明方向正确，不作为强度上限结论。

### 1.3 LLM 可选升级

LLM 席位路径不变：模型只从 `viewFor(seat)` 看自己视角，`parseAgentReply('doudizhu', ...)` 只接受 `bid/play/pass`，再由 Host 当普通动作校验；模型返回非法牌 id / 超时 / 异常一律 `_llmFallback(seat)` 回落本地强化 AI。测试 `llm-seat.test.js` 固定了：

- prompt 暴露 `cardIds` / `pass`，不泄露其他玩家手牌；
- 非法牌被拒后启发式必须落子，不留空转；
- `parseAgentReply` 过滤掉外来字段（如 `targetSeat`）。

## 2. 炸弹猫：完整休想卡（Nope）链

- 新牌种 `nope`，牌库 cycle 中加入 1 张/12 张。
- **反应窗口**：`nopeWindow` 选项（默认 false，注册表里显式开启）。可打断行动：`play` / `draw` / `cats` / `favor` / `attack` / `shuffle2`。发起后除发起者外的存活玩家按座号环形各表态一次（`nope` 或 `passNope`）。
- **链规则**：`pendingNope.nopes` 计数；奇数 → 原行动取消（回合留发起者），偶数（含 0）→ 原行动照常结算。因此「休想卡可被另一张休想卡反制」自然成立。
- **不可打断**：爆炸与拆弹不是玩家行动，不过窗口；`give` 是恩惠的强制回应，也不单独开窗。
- **防绕过**：`beginNope()` 开窗前校验牌是否存在/种类/目标存活，休想卡本身不能被当普通牌打出。
- **AI**：窗口内只用公开信息判断（针对自己 / 别人打 skip / 自己无拆弹牌时有人摸牌）；绝不 peek 牌库顶。
- 快照新增 `pendingNope`（actor / action / targetSeat / nopes / order / responded / awaiting）。

## 3. 大富翁：交易、拍卖、铁路/公用、事件卡、破产清算

### 3.1 交易与拍卖

- `decline`（放弃购买）不再直接结束回合，而是进入 `pending.auction`：起价 = 地价一半，所有存活玩家按环形顺序加价或弃权，价高者得；流拍则保持无主、回合回到发起者。
- 自己回合可 `offer_trade`：`{giveTile, giveCash}` 换 `{wantTile, wantCash}`；对方 `accept_trade` / `decline_trade`。原子交换，任一项校验失败整笔拒绝。有建筑的地产不可交易。
- 接受/拒绝后回合都推进到下一位，避免 AI 反复提同一笔交易形成死循环。
- AI 会参与：拍卖按 `≤ 地价 80%` 且留 200 金安全垫跟价；交易按净收益判定；现金充裕且回合早时主动报价。

### 3.2 铁路 / 公用事业 / 更多事件卡

- 棋盘从 24 格扩到 **32 格**，但**追加而非插入**：0-23 索引完全不变，旧测试与既有存档语义不破坏。
- 新增 4 条铁路（24/26/28/30）与 2 个公用事业（25/29）。铁路租金按持有数 `[25, 50, 100, 200]`；公用事业按骰点 ×（1 个 4 / 2 个 10）。铁路/公用不可建房。
- 机会卡 12 → **20 张**，新增奖金、罚款、向每人收钱、向每人付钱、移动到新资产格等。
- 快照 `board` 数组自动包含新格；`rentNow` 对铁路/公用给出当前租金。

### 3.3 破产清算

`payBank(p, amount, creditor)` 支持债主参数。现金不足时破产者剩余地产（含抵押状态）转给债主而非充公；无债主（银行债务）才回归无主。剩余现金也交给债主。踩别人资产付租与机会卡收付款都传了 creditor。

## 5. 未做 / 已知边界

- DouZero 权重未移植：需要 Python/PyTorch 推理服务，与本项目「零依赖 + 离线可玩」冲突。若未来接受服务端 AI，可另开 `llm`-like provider 接 DouZero HTTP 推理。
- 斗地主 A/B 只有 60 局，未做大样本强度认证。
- 新棋盘 0-23 不变、24-31 追加，视觉上资产类型集中在地图后半段；若要交错布局需重排索引，会破坏旧存档兼容，本轮刻意不做。
- UI 对拍卖/交易/休想窗口没有专用面板：这些动作通过通用 `actions` 列表呈现（label 已写清楚），HTML 按钮细节未单独美化。
