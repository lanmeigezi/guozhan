# 外交潜在恨意、鬻奴令与自动起义（2026-10-30）

本文记录 **grand-front（超大陆 · 十二雄）** 新增的三组规则：

1. **潜在恨意（grudge）**：两国频繁交战/毁约后，双方外交与贸易政策一起转冷；
2. **鬻奴令（xunu）**：颁布后可向相邻势力买奴，奴隶只能当最低级「贼配军」，并持续制造地区动乱；
3. **自动起义（rebellion）**：动乱满 100 后区域脱离原主，原主必须杀光起义民兵；更高民心国家可宣称归附，归附后有征兵敏感期与动乱恢复线。

同时把**地区动乱当前实际效果**完整写在这里，方便后续查询与调参。

> 兼容边界：本次只改 `grand-front`。`warring-states` / `aria` / `iron-front` / `random-front` / `random-front-v2` 的模块表、法令表、contentHash 与 behaviorFingerprint 均不变；旧存档照常读取。
> `grand-front` 因为新增模块 `grudge` + `slavetrade` + `rebellion`、独立法令表 `laws.json`、`governance.json`、`slave-trade.json` 与 `rebellion.json`，contentHash 与 behaviorFingerprint 会变化；**旧 grand-front 存档会 fail-closed，需要开新局**（旧数据不删）。

### 为什么 grand-front 有自己的 `laws.json`

共享的 `config/rules/laws.json` 会被 `contentHash` 纳入。直接往共享表加 `xunu` 会让所有引用它的剧本哈希漂移、旧存档 fail-closed。
因此 grand-front 使用自己的法令表副本（原有 6 条 + `xunu`），只让**这个剧本**承担新哈希。

### 模块顺序（`scenario.json`）

```
economy → statecraft → movement → formation → combat → slavetrade → rebellion → governance → grudge
```

- `slavetrade` 在 `economy` 之后：本回合的税收/军费先结算，买奴再扣金；
- `slavetrade` 也在 `combat` 之后：若卖方源地块在同回合被第三方夺走，交易会以 `REGION_NOT_OWNED` 拒绝（不会从已经不归卖方的地块“凭空买人”）。这是同时提交模型下的确定性顺序，不是偶发 bug。
- `rebellion` 在 `combat` / `slavetrade` 之后、`governance` 之前：本回合战斗/贼配军推高的动乱能在同一回合触发起义；基建不会在起义检查前把 100 压回 99。
- `grudge` 在最后：本回合新宣战/新战斗/夺城产生的恨意能在同一回合被读到最后一次。
- `grudge` 与 `slavetrade` / `rebellion` 都只改 `relations` / 区域 / 单位相关状态，**没有新增 faction 状态**。

## 2. 潜在恨意（grudge）

### 2.1 存储

`GameState.relations[key]` 的 `RelationEntry` 新增三个可选字段：

```ts
interface RelationEntry {
  kind: 'war' | 'alliance' | 'truce' | 'peace' | 'neutral';
  sinceTurn: number;
  grudge?: number;    // 0-100；旧存档缺省 0
  wars?: number;      // 历史宣战次数；旧存档缺省 0
  lastWarTurn?: number;
}
```

- 键仍是 `relationKey(a,b)`（字典序拼接），所以 `(a,b)` 与 `(b,a)` 是**同一条**记录；
- 恨意是**相互的**：同一条记录同时代表双方对彼此的恨意；
- 纯查询函数：
  - `getGrudge(state, a, b)` → 0-100；
  - `tradePolicyBetween(state, a, b)` → `free | restricted | embargo`。

### 2.2 变化规则

| 触发 | 变化 | 写入位置 |
|---|---:|---|
| 主动宣战（`declare_war`） | 双方 +18 | `statecraft.ts` |
| 背弃同盟（`break_alliance`） | 双方 +12 | `statecraft.ts` |
| 进攻自动宣战 | 双方 +18 | `combat.ts` |
| 每场战斗（非中立） | 双方 +2 | `combat.ts` |
| 夺取敌区 | 双方 +5 | `combat.ts` |
| 交战状态每回合 | 双方 +1 | `grudge.ts` |
| 和平/中立/休战每回合 | 双方 -1 | `grudge.ts` |
| 同盟每回合 | 双方 -2 | `grudge.ts` |

- 所有变化钳制在 **0–100**；
- 开局即交战的势力对，初始 `grudge = 25, wars = 1, lastWarTurn = 0`；
- 一次和约**不会清零**恨意，只会让它在和平期缓慢下降；
- 宣战次数 `wars` 由 `set_relation` 进入 `war` 时自增 1；换关系不会丢掉已有 `grudge/wars`。

### 2.3 贸易政策

| 条件 | 政策 |
|---|---|
| 关系 `war` | `embargo`（禁运） |
| 恨意 ≥ 70 | `embargo` |
| 关系 `neutral`，或恨意 30–69 | `restricted`（受限） |
| 关系 `peace`/`alliance`/`truce` 且恨意 < 30 | `free`（通商） |

- `embargo` 时**不能买奴**（拒绝码 `SLAVE_TRADE_EMBARGO`）；
- 政策本身不直接改价；实际报价由 `relationPriceMultiplier` 与恨意附加共同决定。中立关系默认 ×1.25，是常见的“受限但还能做买卖”的价格档；
- 贸易政策是**派生值**，不单独存状态，避免“关系/恨意改了但贸易政策忘更新”的第二份真相。

### 2.4 AI 如何使用恨意

- **进攻**：对恨意 ≥ 60 的目标，进攻门槛降低 0.12（最低 0.9），AI 更愿意打世仇；
- **求和**：只有在“打输了/民心低”且恨意 < 55 时才主动求和；恨意 ≥ 55 宁可继续打；
- **复盘**：`SelfReview.lessons` 会在最高恨意 ≥ 45 时提示“和谈、通商空间收窄，边境需留守军”；
- **快照/UI**：`ProjectedFaction.grudge` 与 `tradePolicy` 只投影给“观看者—该势力”这一对关系；自己不带自我恨意；
- **LLM 提示词**：列国行会显示 `恨意:42｜商路:restricted`，让模型能据此判断外交空间。

## 3. 鬻奴令（xunu）与贼配军

### 3.1 法令

`config/scenarios/grand-front/laws.json`：

```json
{
  "id": "xunu",
  "name": "鬻奴令",
  "description": "默許邊境鬻奴；解鎖向相鄰勢力買奴，全國民心 -2/回合、金 +8%",
  "enactGold": 500,
  "effects": { "moralePerTurn": -2, "goldMultiplier": 1.08 }
}
```

- 颁布时仍按既有规则**一次性 −5 全国民心**（变法生乱，见 `economy.ts`）；
- 持续效果：每回合 −2 民心、金收入 +8%；
- 只有**买方**必须已颁布；卖方不需要同法，但必须满足下一节的贸易条件。

### 3.2 合法动作

`enumerateLegalActions()` 只在以下条件全部满足时生成 `trade_slaves`：

- 剧本有 `world.slaveTrade`；
- 买方 `faction.laws` 含 `xunu`；
- 买方地块与卖方地块**相邻**（无向邻接）；
- 卖方势力存活、关系非 `war`、贸易政策非 `embargo`；
- 卖方地块可卖人口 ≥ 最低数量；
- 买方付得起报价。

一个卖方地块只列一条动作（选买方最靠前的相邻地块），每回合最多 8 条（`perKindCap`）。

命令：

```json
{
  "kind": "trade_slaves",
  "fromFaction": "west",
  "fromRegion": "h01",
  "toRegion": "h02",
  "count": 10000
}
```

- `fromRegion` 必须是 `fromFaction` 拥有的卖方地块；
- `toRegion` 必须是买方自己拥有的地块；
- `count` 必须是 `minPerTrade..maxPerTrade` 的整数（当前 500–10,000）。

### 3.3 可卖人口上限

`slaveSourceCapacity()` 取三者最小值：

1. 源地块**平民人口** = `regionPopulation(baseManpower, development) − 该地块驻军`；
2. 源地块人口 × `maxShareOfRegionPopulation`（当前 25%）；
3. 卖方全国兵源池 `faction.manpower`。

买方地块的人口/兵源不参与本次计算——奴隶是“买来的外来人口”，不占买方兵源池。

### 3.4 价格

```
price = round(
  count / 1000
  × priceGoldPerThousand            // 90
  × relationPriceMultiplier[关系]   // alliance 0.85 / peace 1 / neutral 1.25 ...
  × (1 + grudge / 100 × grudgePriceSurcharge)  // 当前 0.02
)
```

例：10,000 人、和平、恨意 0 → `10 × 90 × 1 = 900` 金；同一笔在恨意 60 时 → 900 × 1.2 = 1,080 金。

### 3.5 成交后的结算

| 对象 | 变化 |
|---|---|
| 买方 | 金 −price；全国民心 −`buyerMoraleCost`（当前 4） |
| 卖方 | 金 +price；全国民心 −`sellerMoraleCost`（当前 3）；兵源 −count |
| 买方目标地块 | 生成/合并一支 `militia`，`troops = count`，`title = 'bandit_conscript'`（贼配军） |
| 事件 | 发出 `slaves_traded`，只投影给买卖双方与观战端 |

- 同回合多笔买奴会合并到同一支贼配军（unit id：`u_<买方>_<turn>_<目标区>_slave`）；
- 奴隶**只能**是 `world.slaveTrade.slaveUnitType` 指定的最低级兵种，grand-front 中为 `militia`；
- 不消耗买方的粮草/兵源；买方的代价是金、民心、以及后续动乱。

> 人口表示边界：本作地块人口是由 `baseManpower × 发展度` 派生的展示值，不是可逐个增减的独立人口表。因此“卖奴”扣的是**卖方全国兵源池**（`faction.manpower`），不会改写地块的 `baseManpower`；地块详情里的人口数在卖奴后不会减少。这是当前数据模型的刻意取舍，避免再引入一份会与派生人口打架的独立人口状态。

### 3.6 贼配军的特殊规则

1. **头衔**：`UnitState.title = 'bandit_conscript'`；快照驻军条目带 `title`，三端 UI 显示「贼配军」。
2. **每回合动乱**：`slavetrade` 模块每回合遍历所有贼配军，每支在所在区追加 `banditUnrestPerTurn`（当前 **+4**）点动乱，原因写作「贼配军扰民」。
   - 地区动乱每回合自然 `-3`（`economy.unrestDecayPerTurn`）；
   - 因此**一支**贼配军净 **+1**/回合，**两支**净 **+5**/回合，三支净 +9；
   - 动乱是**地区性**的，不会直接扣全国民心。
3. **裁军**：贼配军裁掉**不返还兵源**（防止“买奴→裁军”洗人口）；仍可裁掉以减少动乱。
4. **分兵**：分出的新部队**保留**贼配军头衔。
5. **合兵**：只能与同头衔部队合兵；贼配军不能并入普通民兵，普通民兵也不能并入贼配军（拒绝 `MALFORMED_PAYLOAD`）。
6. **战斗**：按 `militia` 的攻/防/移动力结算；头衔不额外加战力，也没有特殊免伤。
7. **被消灭/裁光**：头衔随单位消失；不会把奴隶转成平民。

## 4. 地区动乱现在到底有什么效果

> 这是本次需求里要求“顺便说一下”的部分；以下全部来自代码，不是文案推测。

### 4.1 两个直接乘数

`RegionState.unrest` 取值 0–100，每回合影响**本区**：

| 效果 | 公式 | 当前参数 |
|---|---|---|
| 金/粮产出 | `max(0, 1 − unrest × outputPenaltyPerPoint)` | `0.004`/点 → 100 动乱时产出归零 |
| 守备战力 | `max(0, 1 − unrest × defensePenaltyPerPoint)` | `0.003`/点 → 100 动乱时守备 −30% |

来源：`src/core/unrest.ts`、`src/core/modules/economy.ts`、`src/core/modules/combat.ts`、`config/rules/governance.json.unrestEffects`。

- 只惩罚**本区**；不会按比例扣全国民心；
- **grand-front 启用自动起义**：动乱到 100 会脱离原主（见 4.5）；其他未启用 `rebellion` 的剧本没有自动易主规则；
- 守备变弱会让敌军更容易夺城，这是动乱最危险的间接后果。

### 4.2 每回合的自然变化

`economy` 模块第 5 步对每个辖区执行：

```
本回合动乱变化 = 高税动乱
              + 法令 unrestPerTurn（郡縣制 -2）
              − 自然衰减 3
```

- 自然衰减：`economy.unrestDecayPerTurn = 3`（每回合）；
- **grand-front 特例**：普通区域（没有 `rebellion`）一旦到 100，本回合不再自然衰减/法令降动乱，保证回合末能触发起义；已归附起义区仍正常衰减，否则永远到不了 50 恢复线；
- 高税动乱：`max(0, 税率 − 0.4) × 6 × 100`，即 40% 及以下为 0，45% 为 +30，50% 为 +60，60% 为 +120；
- 基建每级还有 `unrestReductionPerTurn`（Lv1 -1 … Lv4 -5）；
- 贼配军额外 `+4/支/回合`（在 `slavetrade` 模块，晚于 economy 衰减执行）；
- 最终钳制 0–100。

### 4.3 哪些行为会“新增”动乱

新增动乱受**全国民心**放大：

```
factor = 1 + max(0, 60 − 全国民心) / 60 × 1.5
```

即民心 ≥60 不放大；民心 0 时 ×2.5。基础值：

| 行为 | 基础动乱（grand-front） | 作用区 |
|---|---:|---|
| 征兵 | 8 | 征兵区 |
| 一场战斗 | 10 | 交战目标区 |
| 夺城 | 35 | 被夺区 |
| 主动开战动员 | 15 | 进攻出发区 |

来源：`config/scenarios/grand-front/governance.json.lowMoraleUnrest`。共享旧配置 `config/rules/governance.json` 仍是 4/5/25/8，`random-front-v2` 与 `iron-front` 保持旧手感；grand-front 的数值更高，目的就是让“征兵/战火真的能把动乱推到 100”。战报证据里带 `lowMoraleFactor` 与动乱拆分。

### 4.4 UI 表现

- 区域详情显示「地区动乱 X · 状态」；
- 有动乱的区域显示“金粮产出 −x%、守备 −y%”；
- 动乱 ≥50 时 ASCII 地图标注 `动乱N`；
- 动乱 ≥60 时提示尽快用基建/减税/休战压低；
- 贼配军驻军带红色「贼配军」标签；起义/守城民兵显示「起义民兵」「守城民兵」。

### 4.5 自动起义（grand-front）

配置：`config/scenarios/grand-front/rebellion.json`；执行模块 `src/core/modules/rebellion.ts`。

**触发**：区域动乱达到 100，且当前没有 `rebellion` 状态、owner 非空。

**起义时**：

1. 原主军队撤往最近己方区域；无路可退则溃散（不会留在起义区）。
2. 区域 `owner=null`，写入 `rebellion { from: 原主, sinceTurn }`；动乱保持 100。
3. 本区人口（`regionPopulation`）全部化为 **1 支 `rebel_militia`**（低战力民兵，默认战力 ×0.25，`garrisonOnly`，不可移动/进攻/分兵/合兵）。

**未归附阶段**：

- 只有原属国能进攻这个区域；其他国家直接进攻会被 `REBELLION_NOT_YOURS` 拒绝，只能用“宣称”。
- 原属国必须把 `rebel_militia` **全部杀到 0** 才能夺城；只要还有 1 个民兵，就只结算伤亡、不改变归属。
- 重占成功后：清除 `rebellion`，动乱钳到 `originalReoccupyUnrest`（默认 90），避免同回合再次起义。

**外交宣称**：

- 条件：起义民兵仍 >0；宣称国不是原主；宣称国民心 > 原主民心 + `claimMoraleLead`；`claimRequiresAdjacency` 为 true 时才额外要求与起义区相邻（当前 grand-front 配置为 false，任何高民心国家都可宣称）。
- 命令：`{ kind: 'claim_rebellion', regionId }`；合法动作同时显示当前双方民心与起义民兵数。
- 成功：区域归附宣称国，动乱设为 `claimedUnrest`（90）；旧起义军解散，生成 **1 支 `rebel_garrison`**，兵力 = `min(宣称时的起义民兵, claimedGarrisonCap=20000)`；`garrisonOnly=true`，不可调动/分兵/合兵，只守城。
- 宣称为**自动归附**，不消耗金币，但会与“原主只能武力重占”的规则并存：原主和其他国家此后可按正常战争规则进攻该区域。

**归附后的状态**：

- `rebellion.claimedBy`、`claimedTurn` 保留。
- 宣称后的 `claimedConscriptionTurns=3` 个回合内（不含宣称当回合），如果宣称国在该区下 `recruit` 命令，会在本回合末再次起义：区域 owner 变 null，征兵军与守城民兵被起义吞没，重新生成 `rebel_militia`；事件 `cause='claimed_conscription'`。
- 动乱降到 `normalizeUnrest=50` 及以下时，清除 `rebellion`；`rebel_garrison` 转为普通民兵（头衔/锁定解除），区域恢复正常。
- 归附后的特殊状态不会因为时间自动结束；只有“再次起义”或“动乱≤50”两条出口。

**事件**：`rebellion_started` / `rebellion_claimed` / `rebellion_ended`；全部广播。

**快照**：`ProjectedRegion.rebellion = { original, originalName, claimedBy?, claimedByName?, claimedTurn?, rebelTroops, conscriptionTurns? }`；`stacks[].title` 可为 `rebel_militia` / `rebel_garrison`。

## 5. 协议、快照与三端显示

### 5.1 快照

`ProjectedFaction` 新增：

```ts
grudge?: number;                 // 0-100，观看者与该势力的恨意
wars?: number;                   // 双方历史宣战次数
tradePolicy?: 'free' | 'restricted' | 'embargo';
```

`ProjectedRegion.stacks[]` 新增：

```ts
title?: 'bandit_conscript' | 'rebel_militia' | 'rebel_garrison';
```

`ProjectedRegion.rebellion` 新增（partial 可见即下发）：

```ts
rebellion?: {
  original: string;
  originalName?: string;
  claimedBy?: string;
  claimedByName?: string;
```

## 6. 拒绝码

|---|---|
| `LAW_NOT_ENABLED` | 买方未颁布 `xunu` |

## 8. 以后怎么改

### 调数值

只改 `config/scenarios/grand-front/slave-trade.json`：

| 键 | 作用 |
|---|---|
| `priceGoldPerThousand` | 每 1000 奴隶基础金价 |
| `minPerTrade` / `maxPerTrade` | 单次数量范围 |
| `maxShareOfRegionPopulation` | 单次最多买走源区人口比例 |
| `buyerMoraleCost` / `sellerMoraleCost` | 成交即时民心代价 |
| `banditUnrestPerTurn` | 每支贼配军每回合动乱 |
| `grudgeBlock` | 恨意禁运线 |
| `grudgePriceSurcharge` | 恨意加价斜率 |
| `relationPriceMultiplier` | 各关系价格乘数 |

改完重跑 `npm run validate-config` 与 `npm test`。若改的是共享规则（如 `unrestDecayPerTurn`），要意识到它会影响所有启用 governance 的剧本。

起义参数在 `config/scenarios/grand-front/rebellion.json`：

| 键 | 作用 |
|---|---|
| `levyRatio` | 起义民兵 = 本区人口 × 比例（当前 1.0，全部人口） |
| `rebelCombatMultiplier` | 起义/守城民兵战力乘数（当前 0.25） |
| `claimRequiresAdjacency` | 宣称是否要求相邻（当前 false：任何高民心国可宣称；改 true 可限制为边境国） |
| `claimMoraleLead` | 宣称国民心至少要比原主高多少（当前 1） |
| `claimedUnrest` | 归附后的动乱（90） |
| `claimedGarrisonCap` | 归附后最多保留的守城民兵（20000） |
| `claimedConscriptionTurns` | 归附后多少回合内征兵会再起义（3） |
| `normalizeUnrest` | 动乱降到多少及以下恢复正常（50） |
| `originalReoccupyUnrest` | 原主重占后的动乱（90） |

grand-front 的征兵/战火基础动乱在 `config/scenarios/grand-front/governance.json.lowMoraleUnrest`（8/10/35/15）；共享旧配置保持 4/5/25/8，别改错文件。

### 换法令 id

同时改：
1. `config/scenarios/grand-front/laws.json` 的 `id`；
2. `config/scenarios/grand-front/slave-trade.json` 的 `lawId`；
3. 测试夹具里的 `xunu` 引用。

### 把机制带到别的剧本

1. 复制 `config/scenarios/grand-front/laws.json` 到目标剧本目录并加 `xunu`；
2. 复制 `slave-trade.json`；若要自动起义，再复制 `rebellion.json` 与 `governance.json`（后者用于更强的动乱基础值）；
3. 在目标 `scenario.json` 的 `knowledge` 指向这些文件；
4. 在 `moduleOrder` 末尾加 `slavetrade`、`rebellion`、`grudge`；
5. 重跑 `npm test`，并接受该剧本 contentHash/behaviorFingerprint 变化（旧存档需重开）。

### 设计边界

- 目前只有**买方**需要鬻奴令；卖方不需要。若想改成“双方都需同法”，在 `slavetrade.ts` 的 `handleTrade` 加一条 `seller.laws.includes(cfg.lawId)` 校验，并在文档更新拒绝码。
- 目前没有普通贸易/粮食贸易；`tradePolicy` 先服务于鬻奴与 AI 外交，后续若加贸易，直接复用 `tradePolicyBetween()`，不要再造第二套关系判断。
- 恨意是成对记录，不区分“谁更恨谁”。若要做非对称恨意，需要把 `RelationEntry.grudge` 拆成 `grudgeA/grudgeB`，并同步改快照、AI 与 UI——当前刻意不做，避免双份真相。
